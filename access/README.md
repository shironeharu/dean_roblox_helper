# PC 등록·차단 관리

[관리자 폼 열기](https://github.com/shironeharu/dean_roblox_helper/actions/workflows/manage-access.yml)

GitHub 저장소 쓰기 권한이 있는 계정으로 로그인하고 **Run workflow**를 엽니다. 브랜치는 **main**을 선택합니다. 별도 서버나 앱에 내장하는 관리자 토큰은 없습니다.

## 사용자 등록

1. 사용자가 앱의 PC 인증 창에서 **ID 복사**를 누르고 Discord `ddu._.`에게 DM으로 전달합니다.
2. 관리자 폼에서 `action: upsert`를 선택합니다.
3. `pc_id`에 복사한 코드, `name`에 앱 상단에 표시할 이름을 입력합니다.
4. `expires`에 `YYYY-MM-DD`를 입력합니다. 해당 날짜 **한국시간 23:59:59**까지 사용할 수 있습니다. 빈칸은 무기한입니다.
5. 허용하려면 `blocked` 체크를 끄고 실행합니다.
6. 워크플로가 성공하면 사용자가 **로그인**을 다시 누릅니다. GitHub의 파일 전파에는 잠깐 시간이 걸릴 수 있습니다.

## 수정·차단

- 이름/만료일 변경: `upsert`로 같은 PC ID의 값을 다시 입력합니다. 만료일을 빈칸으로 두면 무기한으로 바뀝니다. 차단 상태도 `blocked` 값으로 갱신됩니다.
- 차단: `block`과 PC ID만 입력합니다.
- 차단 해제: `unblock`과 PC ID만 입력합니다. 만료일은 자동 연장되지 않습니다.
- 목록 확인: `list`를 실행하고 완료된 실행의 **Summary**를 봅니다.

기존 항목은 차단/해제 작업으로 이름·만료일이 변경되지 않습니다. 목록은 `registry.json`에 저장되고 앱용 `allowlist.txt`는 자동 생성됩니다. 동시에 여러 등록을 요청하기보다 한 작업이 끝난 뒤 다음 작업을 실행하세요.

## 인증 정책

- PC ID는 시스템 드라이브의 볼륨 식별값과 Windows 설치 식별값을 SHA-256으로 해시한 코드입니다. 원본 식별값은 전송/저장하지 않습니다. 앱은 목록을 내려받아 로컬에서 대조하며 PC ID를 URL로 전송하지 않습니다.
- Windows 재설치·시스템 드라이브 포맷 등으로 PC ID가 달라질 수 있습니다. 그때 새 코드를 등록하고 이전 코드는 차단합니다.
- 앱 시작 시 자동으로 온라인 확인하고 승인된 PC는 바로 메인 화면을 엽니다. 미등록·차단·만료·통신 실패일 때만 등록 화면을 표시합니다. GitHub Contents API로 최신 목록을 받아 raw 파일 캐시 지연을 피합니다. 온라인 확인에 실패하면 기능을 실행하지 않습니다. 미등록·차단·만료 항목은 거부됩니다.
- 실행 중 10분마다 비동기로 재확인합니다. 차단·이름 변경은 다음 성공한 확인 때 반영됩니다. 유효기간은 로그인 시 받은 서버 시각과 단조 증가 타이머로 계산해 앱 실행 중에도 적용합니다.
- 일시적인 통신 실패는 재시도하며 마지막 성공 후 최대 30분까지만 유예합니다. 그 이후에도 확인하지 못하면 기능을 중단합니다.
- 앱 상단은 등록 이름을 표시하며 마우스를 올리면 만료일을 볼 수 있습니다.
- 이 저장소는 공개이므로 등록 이름과 해시된 PC ID, 만료일·차단 상태도 공개됩니다. 이름에는 공개 가능한 닉네임을 쓰고 실명·연락처·결제정보를 입력하지 마세요.
- 인증은 새 인증 버전부터 적용됩니다. 이미 배포된 예전 버전을 원격으로 잠그거나, 수정된 실행 파일까지 강제로 통제하는 DRM은 아닙니다.

초기 목록은 비어 있습니다. PC를 자동 승인하지 않으므로 최초 사용 전에 관리자가 등록해야 합니다.
